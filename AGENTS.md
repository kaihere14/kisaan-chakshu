# Repository instructions

These instructions apply to the entire repository.

- Read [README.md](README.md) before planning or changing the project. It is the shared source of project context, architecture, and implementation status.
- Work in `client/` and `server/`; these replace the original `frontend/` and `backend/` names.
- Before each implementation step, present its design, scope, affected files, and validation approach. Wait for explicit user approval before implementing it.
- Approval for one step does not authorize subsequent steps. Keep changes within the approved scope.
- Follow the route → controller → service → database/external API convention described in the README.
- Do not invent product requirements, provider choices, API contracts, or database designs. Propose unresolved decisions for review.
- Update the README when approved decisions or completed work change the project context. Clearly distinguish planned behavior from implemented behavior.
- Verify approved changes with appropriate checks and report what passed, what failed, and what could not be checked. Never claim empty placeholders are working code.
- Keep credentials out of documentation and version control.
